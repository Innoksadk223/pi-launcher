# PI 项目启动器

一个 macOS 小入口：打开后一眼看到每个项目上次是什么时候开的，点一下就在这个项目里开新会话。启动后窗口不会自动消失，可以接着开下一个；关窗口就退出。

终端可以选：标题栏右上角列出本机已装的终端，Ghostty 与系统自带的 Terminal 都能直接开（都真机验过）；装了别的会检测到、标「未适配」。

界面用 WebKit 渲染（纸卡，昼 / 夜两套），启动与读写走原生代码（Swift）。

## 打开与关闭

- 打开：双击 `PI 项目启动器.app`，或点 Dock 图标。
- 启动项目后窗口**保留**，可以接着开下一个项目。
- 关闭：点左上角红色关闭按钮，或按 `ESC`（没有筛选时）、`⌘W`、`⌘Q`；进程直接结束，不留在后台。
- 没有菜单栏常驻图标，也没有全局快捷键。

## 使用

| 操作 | 效果 |
|---|---|
| **点击卡片** | **在这个项目里开一个新会话**（`pi`） |
| `⌘↵` | 继续这个项目最近一次会话（`pi --session <最近一条>`），没有旧会话时等同于开新会话 |
| 卡片右下角「N 个旧会话 ›」 | 在右侧展开该项目的历史匣，挑一条继续；再点一次同一颗胶囊即收起 |
| 卡片右上角星标 | 设为／取消常用（悬停时出现，占日期那一格） |
| 卡片右上角 ✕ | 从「最近项目」移除（常用项没有这个按钮，先取消星标） |
| 左栏顶部搜索框 | 按名称或路径实时筛选（空格分隔多词＝同时满足） |
| 「常用项目」分组头右侧「+ 添加」 | 选一个文件夹固定到常用区（**不会启动 PI**） |
| 列表末尾「选择文件夹并打开」 | 弹出系统选择框，选完直接在该目录启动 |
| 标题栏「终端 ▾」 | 选用哪个终端开：已安装的才会列出，未适配的灰着不可选 |
| 拖动标题栏 | 移动窗口。标题那一条整条可抓（左边 84px 留给红绿灯）；其余区域是网页内容，不响应拖动 |
| 左上角 X · `ESC`（无筛选） | 退出 App，不留在后台 |

列表末尾入口在空项目、搜索有结果和无结果时都保留。卡片是两行分槽：上行项目名、点线、日期与悬停工具；下行路径与「N 个旧会话」胶囊。两行物理隔开，悬停浮出的星标／✕ 与常驻的会话胶囊不会叠在一起。没有旧会话的卡片只写「还没有旧会话」，也不给胶囊。

「添加常用项目」不再常驻底栏：底栏只留左状态、右快捷键。入口搬到「常用项目」分组标题右侧，这个分组**一律渲染**，一个常用都没有时里面是一条虚线提示行，所以入口不会因为「空的」而消失。

## 键盘

**单栏**：`↑` `↓` 选择 · `↵` 新会话 · `⌘↵` 继续上次 · `⌘F` 搜索 · `ESC` 清空筛选（没筛选时退出 App）

**展开右匣后**：`Tab` 在左右两栏间切换键盘焦点 · `↑` `↓` 在焦点那一栏里选 · `↵` 左栏开新会话 / 右匣恢复会话 · `ESC` 先清当前栏筛选，没筛选就收起右匣，都没开着才退出 App

搜索框聚焦时，`↑` `↓` 依然会移动选中项（v2 里打字时会「盲选」，已修）。`Enter` 或空格只触发当前聚焦的按钮，不会误开项目。中文输入法选词时的 `Enter` 被识别为组字确认，不会触发启动。

## 历史会话

- 入口是卡片右下角的「N 个旧会话 ›」胶囊；点卡片本体是**开新会话**，两者不同。右匣开着时点别的卡片仍是开新会话，点别的卡片上的胶囊才把右匣切到那个项目。
- 右匣是一只独立的纸盒，标题行有项目名、路径、条数，右上角是「+ 开新会话」与「⧉ 收起 ESC」两个实体按钮——不再靠一行 10px 灰字返回键。
- 右匣有自己的筛选框，只筛会话标题；左栏的搜索框只筛项目，两边互不影响。
- 只列**当前项目**里最近活动的 **10 条**会话，由新到旧；更早的记录不在启动器内显示，也不扫描其它项目。
- 每条显示：首问标题（截断到 1 行）、最后活动时间、消息条数。
  - 标题重复很常见（同一个项目里反复问类似的事），所以**排序依据是时间，不是标题**。
  - 时间读的是会话文件里最后一条消息的时间，不是文件 mtime（mtime 会偏晚，实测最多差 7 小时）。
- 点一条即在当前选中的终端里 `pi --session <会话文件>` 继续；**不 fork、不分支**。
- 启动时只为已记录项目读标题/时间/条数摘要；完整会话列表仍只在点「历史」时读取当前项目目录。
- 「已经在跑就直接切过去」只有 Ghostty 能做到（它的终端有工作目录属性）；Terminal 查不到，所以继续时会新开一个窗口。

## 数据位置

```
~/Library/Application Support/PI Project Launcher/
├── projects.txt     项目列表
└── terminal.txt     选中的终端 id（ghostty / terminal）
```

`projects.txt` 格式：每行一条，`F` = 常用，`R` = 最近，制表符后为绝对路径。

```
F<Tab>/Users/you/projects/我的项目
R<Tab>/Users/you/projects/另一个项目
```

不存在的目录在读取时会被自动跳过。删除该文件即可恢复初始状态（不会报错）。

`terminal.txt` 只一行终端 id。文件不在、写了个不存在的 id、或那个终端已经卸载，都回落到第一个能用的（先 Ghostty，再系统 Terminal），并在底栏说一句。

## Windows 版

Windows 上跑的是同一个界面，外面换了一个 Tauri 2 外壳（Rust + 系统自带 WebView2）。交付物是**单文件便携 exe**，双击就能用，不需要安装。

```bash
# 从源码构建（需要 Rust 与 Node）
cd win
npm install -g @tauri-apps/cli@2
npx tauri build --no-bundle      # 产出 win/src-tauri/target/release/pi-launcher.exe
```

推送到 `main` 时 GitHub Actions 会同时出两个包；打 `v*` 标签时挂到 Release：

| 平台 | 产物 | 说明 |
|---|---|---|
| Windows | `pi-launcher-<版本>-windows-x64.exe` | 单文件，免安装 |
| macOS | `pi-launcher-<版本>-macos-arm64.dmg` | 拖进「应用程序」 |

第一次双击 exe 会弹 SmartScreen（没有代码签名），点「更多信息 → 仍要运行」。

**前提**：本机要有 `pi`（能在命令提示符里直接敲 `pi`），以及 Windows Terminal。系统还要有 WebView2——Windows 11 和更新过的 Windows 10 都自带。

数据放在 `%APPDATA%\PI Launcher\`，和 Mac 版同构：

```
%APPDATA%\PI Launcher\
├── projects.txt     项目列表（F/R + 制表符 + 绝对路径）
└── terminal.txt     选中的终端 id
```

和 Mac 版的差别，只有这几处：

- **终端**：只认 Windows Terminal（`wt.exe`）。没装时底栏直接说一句「没找到 Windows Terminal」，不回落别的终端。
- **继续会话不切已开窗口**：Mac 上「继续」会先找 Ghostty 里已经开着的那个窗口并切过去；Windows 一律开新窗口。
- **窗口键自绘**：无边框窗口，标题栏右侧的「— □ ×」是画在页面里的；标题栏可拖动，双击最大化。
- **快捷键**：`⌘↵` → `Ctrl+↵`，`⌘F` → `Ctrl+F`，`⌘W` → `Ctrl+W`；`ESC` 不变。
- **字体**：项目名用系统自带的宋体（SimSun），正文 Microsoft YaHei UI，等宽 Cascadia Mono / Consolas。

启动链路是 `wt.exe -w new new-tab -d <项目> cmd /d /v:off /c <pi 命令>`。三层都会改引号，改这段之前先看 `win/src-tauri/src/launcher.rs` 里 `cmd_quote_arg` 的注释——外面那对引号是 Windows Terminal 补的、cmd 剥的，自己再包一层会把整条命令粘成一个程序名。

## 视觉

整套界面是**纸卡**：暖白纸、墨黑字、宋体项目名、等宽日期。共享材质包（`ui/tokens.css` + `ui/glass.css`）保持与风格包逐字节一致，只借它两样东西——整窗那一层磨砂板，和表面的颗粒；其余组件全部在 `ui/app.css` 里重写。

三层，从上到下：

| 层 | 用在哪 | 边界从哪来 |
|---|---|---|
| 板 `.lg-slab` | 整个窗口 | 顶部高光往下褪 + 颗粒；底唇高度设为 0，纸不需要凸起的边 |
| 纸 `.card` | 每张项目卡 | 画布比纸深一档 + 1px 实线描边 + 短影 |
| 线 `.group__head` | 分组标题 | 标题后面拖一条发丝线，右侧是数量 |

**边界不清楚是靠对比解决的**：画布 `#eee8da`、卡片 `#faf7ef`，两者差一档；卡片再自带 1px 描边和 2px 内的短影。不靠分割线暗示「这里有一条」。

**一张卡从左到右**：

```
[文件夹图标] [01] 项目名 ·············· 今天 10:42
                  ~/路径                  21 个旧会话
```

项目名用宋体（`Songti SC`），日期和会话数用等宽（`SF Mono`），中间那条点线把两者连起来，像目录页。序号与图标是全局连续的，不随分组重排。

**选中和状态是两件事，视觉上分得开**：

- 选中＝赭红描边 + 5% 赭红底 + 名字下划线 + 赭红序号／日期。
- 状态＝左侧 3px 条：正在打开／已打开是赭红，启动失败是砖红。两者能同时出现。
- 路径失效＝虚线边 + 划掉；无旧会话＝图标退一档。

**昼夜两套**。夜里不是反色，是同一张纸换成台灯下的样子：画布 `#12110c`、纸 `#24211a`、墨色 `#f2ecdd`、赭红提亮到 `#e58f70`。卡片相对画布提亮一档，颗粒混色换成 `screen`。切换在标题栏右上角，两个字（昼 / 夜），首次启动跟随系统外观，之后记住手动选择。

**终端选择在标题栏右侧、昼夜开关左边**：等宽小字写当前终端名加一个下拉尖，点开是一张小纸卡菜单（纸底 + 1px 描边 + 浮起投影）。当前项右侧标赭红「当前」，未适配的灰着标「未适配」。标题栏这层的拖动落点由页面实测右侧控件宽度后让出（`window.__titlebarInsets`），不再手抄 CSS 内距。

**配色只用四档**：纸、墨、灰（路径／日期）、赭红。赭红只出现在选中、常用星标、主操作的悬停和失效提示，其余一律中性。

实测对比度（昼夜各取整套卡片）：名称 16.8 / 13.6，路径与日期 6.7，赭红文字 5.4 / 5.2，主按钮 14.7 / 16.0，全部过 4.5:1。

**磨砂靠颗粒，不靠模糊**。`backdrop-filter` 在自绘画布上几乎看不出效果（背后是自己画的渐变，不是照片），所以表面叠了一层内联 SVG 湍流颗粒（120×120，白天 13%、夜里 10%）。近看有颗粒，正常距离仍是纸面。

启动器对共享风格包的调整：

| 项目 | 风格包 | 这里 | 理由 |
|---|---|---|---|
| 正文 | 15px | 14px 起，路径 11px、日期 10.5px | 中文小字必须够大；并关掉 `-webkit-font-smoothing: none` |
| 卡片圆角 | 面板 32px | 卡片与搜索框 3px，工具键 2px | 纸的边是直的，圆角只用来收口 |
| 卡片体积 | 顶沿高光 + 渐变描边 + 投影 | 1px 实线 + 短影 | 棱角留给纸，不留给玻璃 |
| 板的圆角 | 面板 28px | 0 | 窗口本身是方的，板再圆角会在四角露出画布 |

**不做透壁纸的窗口级毛玻璃**。实测正文墨色压在桌面深色区上对比度只有 1.02–1.77（AA 要求 4.5），不可读。所以底色由页面自绘，窗口不透明；窗口底色（`src/main.swift` 的 `windowBaseDay/Night`）也同步成纸色，加载那几帧不会闪白或闪绿。

## 交互细节

- **加载态分三段**：点下去底栏写「正在开新会话…」，卡片左侧出 3px 赭红条、日期位置换成「正在开新会话」；窗口开出来后写「已在 Ghostty 开窗口，等 pi 起来…」；确认到 `pi` 真的在这个目录里跑起来，才写「已开好新会话」。每个请求 ID 由当前页面代际加页内递增序号组成；选目录在打开面板前就登记意图，未返回前不启动 30 秒兜底；面板返回只补项目并复用同一个号，取消则释放。
- **「跑起来」怎么确认**：看进程，不看文件。会话文件靠不住——实测 `pi` 启动后只建会话目录，`.jsonl` 要等你发第一条消息才落地；而 `pi` 是 node 起的（进程名不是 pi），所以用 `proc_pidinfo` 找「以这个项目目录为工作目录、且是这次点击之后才启动」的进程（`src/ProcessProbe.swift`）。多个启动请求共享同一个监测器：立即首检，每轮只取一份 PID 快照，按请求分别匹配；最后一项完成或超时就停。
- **状态会自己结束**：完成类（已开好 / 已继续 / 已切换终端）4 秒后自动消失；进行中一直亮着，直到被下一相覆盖；失败红字留到下一次操作。
- **不谎报成功**：新会话的 12 秒从终端调用返回后算；期间没监到那个进程，就写「已开窗口，但没等到 pi」，不说「已开好」，也不把进程出现当成 PI 已可输入。
- **界面自己也能兜底**：点了卡片 30 秒没收到任何回应，撤掉那一张卡的 loading 并提示「没等到回应，请重试」。`pending` 按请求 ID 分别记，连点同一项目或不同项目时，旧请求只清自己的计时器；迟到消息用项目内已接受的页内序号、活跃请求和最后状态判断，不用墙钟时间，`panel` 标记本身不是新旧证明。旧请求没有活跃登记或回放资格时按 requestId 里的页面代际丢弃；有活跃登记的终态仍按自己的 ID 收尾。重载只导入由当前投递页确认的活跃请求快照和最近状态，终态回放不建 loading。项目移除会清掉该项目的 pending 和展示记录；未登记的旧消息没有正证，直接丢弃。普通 push 的 replay 标记不能取得登记资格，只有当前投递页的快照导入可以；每个页面代际只消费一次快照，同页重复 ready 不重发。加常用、切终端这类状态不属于启动，不会误撤启动中的卡片。
- **失效路径**：文件夹被删后卡片变成虚线框、名字划掉，日期位置写「路径失效」，点击只给提示、不启动。
- **取消常用不会丢项目**：取消星标后降到「最近项目」。
- **仅错误弹提示**：成功只在底栏写一行状态，失败才弹提示条（原因在提示条，底栏写「打开失败」）。
- **保存失败会回滚**：写盘失败时内存状态回退并明确提示，不谎报成功。
- **刷新不跳顶**：数据没变就不重绘；变了也保留原来的滚动位置。

## 首次运行可能需要的授权

**macOS**

- 系统可能弹「允许“PI 项目启动器”控制“Ghostty”（或 Terminal）」：需要点允许，否则无法开终端窗口。
- 若之前拒绝过，到「系统设置 → 隐私与安全性 → 自动化」重新勾选。
- 若 Ghostty 配置里写了 `macos-applescript = false`，需改回 `true`。

**Windows**

- 只有一条：第一次双击 exe 时 SmartScreen 拦一下，点「更多信息 → 仍要运行」。没有别的授权要开。

## 说明与边界

- 只显示你手动添加／打开过的项目，**不自动发现**磁盘上的其它项目。
- 启动准备：页面开始加载后，项目列表在后台读取，终端安装检测在主线程并行进行；三路（页面、项目、终端）都到齐才应用一致快照。准备完成前依赖项目/终端的动作排队；主题与退出不等待。
- 摘要由协调器按项目去重/合并/取消，只刷新受影响项目；继续/复用已有项目也会检查该项目的文件变化并复用有界缓存。已有星标/重排不重读历史；从未记录过的项目首次加入常用时只刷新该目标。移除项目会清缓存，数据没变不重复推送。增量快照里缺失的目标会移除旧摘要；空目标会取消旧工作；页面重载会重发当前数据、由当前投递页确认的活跃请求和最近状态快照，旧页或旧快照不会落地。
- 退出后生命周期门会拒绝仍在排队的主线程回调，后台 Store/历史/摘要/进程监测结果不会再启动窗口或写“最近”。
- `NSAppleScript` 只在主线程创建、执行和读取结果；Ghostty 冷启动等待拆成可取消的分步调度，开窗与命令各只提交一次。查运行状态/已有窗口先用 `application is running`，不靠 `tell` 触发启动；未知/拒绝/超时的查询结果不会被当成“没找到”去盲目开窗。
- 「继续」时（仅 Ghostty）会先查这个项目是否已经有窗口：明确找到就切过去，只报告“已切到该项目的已有窗口”，不核实其中是否还在运行 PI；明确没找到才回落开窗；查询失败/拒绝/超时只报告，不盲目重试。开新会话一律新开窗。系统 Terminal 查不到工作目录，一律新开。
- 开窗或命令交付成功只代表终端收到了动作，不代表 PI 已出现可输入界面；启动器只监测，不接管或终止终端/PI。
- 标题栏让位宽度只在初次加载、窗口缩放或当前终端标签变化时重新测量，并合并同一轮请求；拖动落点与窗口缩放行为不变。
- 只适配了 Ghostty 与系统 Terminal。其它终端（iTerm2 / Warp / kitty / WezTerm / Alacritty / Hyper / Tabby）会被检测到，但标「未适配」、不可选——没实测过就不声称能用。
- 会话索引只读标题、时间、条数，**不读取也不展示聊天正文**。
- 界面回传的会话路径会在原生侧重新核验（必须属于该项目的会话目录），核验不过不启动。
- 路径含中文、空格、单引号均已实测正常（Ghostty 走环境变量，Terminal 走 POSIX 单引号）。
- 依赖：已安装 Ghostty 或系统 Terminal，且登录 shell（`/bin/zsh -lc`）中能找到 `pi`。
- 仅 macOS。用系统自带 WebKit（不需要完整 Xcode）。

## 构建

```bash
cd pi-project-launcher

```

构建会**先跑自检**，未通过则中止。输出 `PI 项目启动器.app`。


## 验证工具

```bash
# 多宽度截图（直接读本地 ui/，不需要 HTTP 服务）
# 第三个参数 day|night 决定主题，夜里那组的文件名带 -night 后缀
swiftc -O -parse-as-library -o /tmp/shot tools/shot.swift
/tmp/shot ui /tmp/shots day
/tmp/shot ui /tmp/shots night

# 对比度、点击区、卡片状态、圆角刻度、溢出
swiftc -O -o /tmp/check tools/check.swift
/tmp/check ui day
/tmp/check ui night

# 真实开一个窗口，校验唯一临时目录、完整独占回执、PID 身份、参数与窗口观察
# 记录脚本只证明启动器/终端命令链路，不证明真实 PI 已可输入或真实 App 关闭重开
swiftc -O -parse-as-library -o /tmp/e2e tools/e2e.swift src/Store.swift src/SessionHistory.swift src/Launcher.swift src/Terminal.swift src/ProcessProbe.swift
/tmp/e2e ghostty new
/tmp/e2e terminal continue
# 需要观察启动器退出后终端/PID 仍存活时：
/tmp/e2e ghostty new --keep
```

`tools/e2e.swift` 使用本次新建的唯一临时目录（目录名刻意包含中文、空格和单引号）和本轮唯一脚本，回执先写临时文件再原子发布；发送任何信号前会以精确相等的内核启动时间、cwd 和脚本身份重验本轮进程，无法证明归属就不发信号、不删目录。发送 SIGTERM 后也不自动删除 workspace，只输出 `CLEANUP-PENDING` 路径，并把 PID、内核启动时间、cwd、脚本、信号结果和未知退出状态写入 `cleanup-pending.txt`；未知不报告为已退出或已清理，请后续验收确认无占用后手动清理。窗口 ID 差集只作观察，不用于归属 PASS，也不关闭任何窗口。`--keep` 保留本轮测试进程约 120 秒（至少 60 秒可观察），脚本每 5 秒写 `heartbeat.txt`；不发送信号、不删除 workspace。CLI 退出后进程存活只证明记录脚本链路，不等于真实 App 关闭重开或真实 PI 验证；真实 Ghostty/Terminal 的“继续最近/指定历史”和 PI 可输入状态仍需单独运行应用验证，不能由记录脚本替代。`tools/check.swift` 在 `file://` 下读不到 CSS 规则（跨源限制），所以可访问性改由**实际计算样式**判定；对比度按半透明层逐层合成到不透明底再算，不是简单读 `backgroundColor`。渐变背景没法直接取样，探针会从计算后的 `backgroundImage` 里解析出每个色标按 alpha 加权求平均；写死一个平均色会让暗色永远测不准。垫最底下的不透明色由 `day|night` 参数给（白天 `#c6dacd`、夜里 `#101d18`），取画布最深的一端，是最保守的估计。
